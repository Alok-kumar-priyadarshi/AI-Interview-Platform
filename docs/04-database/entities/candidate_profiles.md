# Purpose

The `candidate_profiles` table stores the structured profile generated by the
AI Resume Analysis pipeline.

It converts an unstructured resume into normalized, queryable information used
by downstream AI systems.

This table becomes the primary knowledge source for interview generation.

---

# Responsibilities

The candidate_profiles entity is responsible for:

- Structured resume representation
- Skills extraction
- Education extraction
- Experience extraction
- Project extraction
- Certification extraction
- Resume summary
- AI confidence tracking
- Profile versioning

It is **not** responsible for:

- Resume file storage
- Interview history
- Evaluation results

# Business Rules

- Exactly one active profile per resume.
- Profiles are generated only after successful parsing.
- Manual editing is not allowed in Version 1.
- Reprocessing creates a new profile version.
- Previous versions may be archived for audit purposes.

# Security Considerations

Candidate profiles may contain personally identifiable information.

Sensitive data should:

- Never be exposed without authorization
- Be included only in authenticated API responses
- Be encrypted in backups
- Be excluded from logs

# SQL Example

```sql
CREATE TABLE candidate_profiles (
    id UUID PRIMARY KEY,
    resume_id UUID UNIQUE NOT NULL REFERENCES resumes(id),
    profile_version INTEGER NOT NULL DEFAULT 1,
    professional_summary TEXT,
    total_experience_years DECIMAL(4,1),
    highest_education VARCHAR(255),
    current_job_title VARCHAR(255),
    current_company VARCHAR(255),
    skills JSONB NOT NULL,
    education JSONB NOT NULL,
    experience JSONB NOT NULL,
    projects JSONB NOT NULL,
    certifications JSONB NOT NULL,
    languages JSONB NOT NULL,
    ai_confidence_score DECIMAL(5,2),
    ai_model_version VARCHAR(50),
    extraction_status VARCHAR(30) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```
